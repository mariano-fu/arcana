# T0.3b — iOS install + offline check

Goal: before building features, prove the core iOS assumption from `specs/plan.md`.
She installs the PWA once from the real homelab hostname with Tailscale on. After
that, the app opens with Tailscale off and with no network at all.

What gets served is the T0.3 hello-world build. There's no Caddy and no API yet:
`tailscale serve` serves `dist/` directly.

URL: `https://<host>.<tailnet>.ts.net/`. `<tailnet>` is the MagicDNS suffix
shown by `tailscale status --json`. It's kept out of this public repo.

## 0. Prerequisites (once)

- Tailscale admin console → DNS: MagicDNS on, **HTTPS Certificates** enabled.
- Her iPhone can reach `<host>`. Either share the `<host>` machine with her
  Tailscale account (admin console → Machines → <host> → Share), or log her
  iPhone into the tailnet.
- Her iPhone has the Tailscale app installed and connected.

## 1. Build (on the dev machine)

```sh
cd web
npm ci
npm run build   # → web/dist/, ends with "precache 12 entries"
```

## 2. Copy `dist/` to the host

From the repo root on the dev machine:

```sh
ssh <user>@<host> 'mkdir -p ~/arcana/dist'
rsync -av --delete web/dist/ <user>@<host>:~/arcana/dist/
```

The trailing slashes matter: they copy the *contents* of `dist/` into `~/arcana/dist/`.

## 3. Serve it on the host

On the host:

```sh
sudo tailscale serve --bg "$HOME/arcana/dist"
tailscale serve status   # should show https://<host>.<tailnet>.ts.net → path
```

`tailscale serve` needs an absolute path. `--bg` keeps serving after the shell exits,
including across reboots, until it's turned off (step 6).

## 4. Check it from the dev machine

```sh
URL=https://<host>.<tailnet>.ts.net
curl -sI $URL/ | head -1                                    # HTTP/2 200
curl -sI $URL/sw.js | head -1                               # HTTP/2 200
curl -sI $URL/manifest.webmanifest | grep -i content-type   # note the value
```

The first request can take a few seconds while the TLS certificate is provisioned.
Ideally the manifest's content type is `application/manifest+json`. Safari is
lenient about this, but record what you see in the results below.

Optional: open the URL in desktop Chrome → DevTools → Application. The Manifest
panel should have no errors and the service worker should be "activated".

## 5. Install and test on her iPhone

With Tailscale **on**:

1. Open Safari (not another browser) and go to `https://<host>.<tailnet>.ts.net/`.
2. Check that the hello screen appears ("Le damos la bienvenida").
3. Compartir → **Agregar a inicio**. Check that the name shows "Arcana" and the icon is the dark card with a star.
4. Open the app from the home-screen icon. Wait ~10 s so the service worker
   finishes caching, then close it.

With Tailscale **off**:

5. Force-quit the app (swipe it away in the app switcher), then open it from the icon.
   → Expected: the hello screen loads, with no error page.
6. Turn on **airplane mode** (Wi-Fi off too), force-quit, open again.
   → Expected: same hello screen.
7. Optional: restart the iPhone, keep airplane mode on, open the app.
   → Expected: still works.

Then turn Tailscale and the network back on.

## 6. Clean up (optional)

Leave it running if you want the installed app to keep receiving updates (redeploy =
steps 1–2 again; the app picks up the new version on its next launch with Tailscale on).
To stop serving:

```sh
sudo tailscale serve --https=443 off
```

## Results

Date: 2026-10-18. iPhone 15, iOS 26.6.1.

Served headers, checked from the dev machine with the step 4 commands:

```
/                       HTTP/2 200
/sw.js                  HTTP/2 200
/manifest.webmanifest   HTTP/2 200, content-type: text/plain; charset=utf-8
```

`tailscale serve` doesn't know the `.webmanifest` extension and sends `text/plain`.
Safari installed the app fine anyway (run 2), so this doesn't block anything.

### Run 1: fail (opened from WhatsApp)

The link was opened from a WhatsApp message, so it loaded in WhatsApp's in-app
browser. "Agregar a inicio" from there only creates a bookmark that opens in the
browser. It doesn't install a standalone web app, so the offline steps weren't run.

### Run 2: pass (opened in Safari)

| Item | Result |
|---|---|
| Date | 2026-10-18 |
| iPhone model / iOS version | iPhone 15 / iOS 26.6.1 |
| Tailscale access (shared node / joined tailnet) | Shared node (the host shared to her account) |
| `manifest.webmanifest` content type | `text/plain; charset=utf-8` (not `application/manifest+json`; Safari accepted it) |
| Installed from Safari with the correct name + icon | Yes. Agregar a inicio with "Abrir como app web" on |
| Opens standalone (no Safari UI) | Yes |
| Opens with Tailscale off | Yes |
| Opens in airplane mode | Yes |
| Opens after a phone restart (optional) | Not tested |
| Status bar / safe area looks right | Mostly. Content starts below the status bar, with no overlap with the clock or Dynamic Island. The status bar band renders plain white, slightly different from the page background. The home indicator sits over the page area |
| Surprises / notes | Run 1: an in-app browser (WhatsApp) can't install the PWA. iOS 26 shows an "Abrir como app web" toggle in the Agregar a inicio sheet, and it must stay on |

**Conclusion:** pass. The core iOS assumption holds: once she installs it from
Safari over Tailscale, the app opens offline with Tailscale off. `specs/plan.md` now
says the install has to be done from Safari itself, not from a link opened inside
WhatsApp or Instagram. Follow-ups added to `specs/tasks.md`: T4.1 (Caddy serves
`.webmanifest` as `application/manifest+json`) and T1.7 (bottom navigation respects
the bottom safe-area inset; status bar color matches the app background).
